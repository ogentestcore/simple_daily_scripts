# Сводка проекта: видео-инструменты (yt-dlp / Whisper / переводчики / ffmpeg)

Обновлено: 16.10.2026 · Технических запросов обработано: 25 · Файл перезаписывается при каждом обновлении.
Оборудование пользователя (со слов): GT 1030 (2 ГБ видеопамяти — для LLM непригодна), Xeon v4 (2016); всё считается на CPU. Цель: передать инструмент коллеге, чтобы тот сам скачивал видео и смотрел его на незнакомом языке с русскими субтитрами.

## Результаты (файлы)

| Файл | Назначение | Статус |
|---|---|---|
| `video_to_ru_subtitles.py` | Видео (ссылка / файл / список .txt/.docx) → текст (субтитры YouTube с согласия пользователя или Whisper large-v3) → перевод (Gemma по умолчанию / OPUS-MT) → субтитры (`srt` рядом / `soft` дорожкой / `burn` вшить); меню качества скачивания (max/1080/720/480); склейка видео списка в один файл. Ключи: `--mode --translator --model --quality --captions --glue/--no-glue --compare --engines` | Готов; части проверены на реальном железе, остальное — на заглушках и сгенерированных видео |
| `compress_video.py` | Отдельный скрипт: сжатие видео до 1080/720/480p или «исходный размер» (файл / папка / список) | Готов; проверен на сгенерированных видео |
| `facebook_download.py` | Скачивание видео Facebook (одиночная ссылка или batch из .txt/.docx), куки, логи сбоев | Готов; ждёт куки браузера |
| `README.md`, `requirements.txt` | Инструкция и зависимости для коллеги | Готовы |

## Обнаруженные проблемы и их решение (с начала проекта)

### Facebook-загрузчик
1. Ошибка записи файла `[Errno 2]` — длинные названия → `trim_file_name`, `windowsfilenames`, `[id]` в имени.
2. `Cannot parse data` на `/reel/` — первичный диагноз («баг yt-dlp») был НЕПОЛНЫМ: лог показал «нужен вход» → куки (`COOKIES_FROM_BROWSER`/`COOKIES_FILE`). **Ждёт выбора браузера.**
3. Лог ошибок разделён на details и retry; fallback `/reel/` → `/watch/`, `mbasic` (эффективность не подтверждена).

### Конвейер субтитров
4. Файл от другой нейросети: не вшивал субтитры, выдавал непереведённый текст за перевод, ломался при повторе → переписано в один файл.
5. Меню не появлялось в VS Code → меню по умолчанию + понятное сообщение без stdin.
6. Перевод 7B-LLM 30+ минут на CPU → быстрые движки, `--compare`, оценка времени.
7. OPUS `model.bin` отсутствовал в последней версии стороннего репозитория → поиск последнего коммита с файлом (сработало).
8. **Моя ошибка:** флаг `fix_mistral_regex=True` ломал токенизатор NLLB (зацикленный мусор) — откатила и оставила предупреждение в коде.
9. Потери предложений у нейропереводчика → перевод по предложениям; обрезанные реплики Whisper → склейка в предложения с делением перевода по таймингам.
10. Склейка путала реплики на китайском → для zh/ja/ko отключена (`MERGE_SKIP_LANGS`).
11. Для передачи коллеге: режим `srt`, кэш распознавания по модели Whisper, Whisper large-v3 по умолчанию.
12. Результаты `--compare` на 4 языках: Gemma лучшая и единственная годная для японского; OPUS быстрый, для японского ненадёжен; NLLB нигде не лучший → **NLLB удалён** (в коде заметка, как вернуть). Пользователю выдана команда удаления кэша NLLB.
13. Пакетная обработка списков: сбой одного видео не останавливает остальных, итог + `work/retry_*.txt`; модель Whisper грузится один раз.
14. Меню качества: ограничение по МЕНЬШЕЙ стороне кадра (`format_sort res:N`) — вертикальные ролики не ужимаются; проверено по документации yt-dlp.
15. Склейка видео: без перекодирования, если форматы совпадают (проверка длиной результата с автооткатом на перекодирование); иначе нормализация к формату первого ролика (тишина для роликов без звука); субтитры подстраиваются под режим (srt / soft — один .mkv / burn — вшиваются при нормализации); время общего .srt сдвигается на длительность предыдущих.
16. **Субтитры YouTube вместо Whisper (с согласия пользователя):** варианты — готовые от автора (на русском — без перевода), готовые на другом языке (переведём сами), автосубтитры оригинала, автоперевод YouTube. Скачиваются ОТДЕЛЬНЫМ запросом (формат json3), чтобы сбой (в т.ч. 429 на автопереводе) не мешал скачиванию видео; при любой неудаче — Whisper. Разбор json3 убирает повторы «бегущих» автосубтитров и строки вроде `[Music]`. По умолчанию (Enter) — только готовые субтитры автора.
17. `compress_video.py`: расширение по меньшей стороне кадра, не увеличивает, чётные размеры, пропуск уже малых, удаление результата, не ставшего меньше исходника.

## Замеры на роликах пользователя (по 20 реплик; с/реплика)

| Движок | ja | zh | de | es |
|---|---|---|---|---|
| OPUS-MT | 0,05 | 0,04 | 0,08 | 0,04 |
| TranslateGemma 4B | 3,7 | 3,2 | 3,1 | 2,5 |

Gemma на 1000 реплик ≈ час на старом CPU; OPUS ≈ минута. Gemma лучше читается, но иногда молча искажает смысл. Французский не проверялся.

## Проверено и не проверено

- Проверено на реальном железе пользователя: скачивание, распознавание, загрузка моделей, `--compare` на ja/zh/de/es.
- Проверено на настоящем ffmpeg (сгенерированные видео): склейка (копирование, перекодирование, burn, soft, откат), сжатие.
- Проверено на заглушках: меню, ключи, пакет, кэш, склейка предложений, YouTube-субтитры (разбор json3 на синтетических данных, варианты, политики, сбой 429, пакет).
- НЕ проверено: **разбор субтитров на живом YouTube** (формат json3 и имена дорожек `…-orig` взяты из документации/описаний; при расхождении сработает откат на Whisper), склейка и пакетное скачивание реальных видео, `compress_video.py` на видео с метаданными поворота и на Windows, полный прогон на компьютере коллеге, французский, Facebook с куками, скорость Whisper large-v3.

## Открытые вопросы / следующие шаги

- Пользователю: прогнать `--captions ask` на 2–3 реальных YouTube-видео (с готовыми субтитрами автора и только с автоматическими) и сообщить, как отработало.
- Железо и система коллеги (хватит ли ему large-v3/Gemma; запасной путь — `WHISPER_MODEL_SIZE="medium"/"small"`, `--translator opus`).
- Возможные доработки: главы с названиями роликов в склейке; глоссарий имён (ошибки вроде «ペリカ» → «пеликан»); сохранение прогресса перевода по пачкам.
- Браузер, залогиненный в Facebook (для кук).
