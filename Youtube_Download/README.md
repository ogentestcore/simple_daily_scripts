# Видео на незнакомом языке → русские субтитры

Скрипт `video_to_ru_subtitles.py` скачивает видео по ссылке (или берёт файл с диска),
распознаёт речь, переводит на русский локально и кладёт субтитры рядом с видео.
Всё считается на вашем компьютере; интернет нужен для скачивания видео и моделей при первом запуске.

## Установка (один раз)

1. **Python 3.10+** (автор запускал на Python 3.13, Windows).
2. **Библиотеки:** `pip install -r requirements.txt`
3. **ffmpeg** — https://www.gyan.dev/ffmpeg/builds/ , папку `bin` добавить в PATH.
4. **Для YouTube — deno.exe** (https://github.com/denoland/deno/releases/latest): положить рядом со скриптом.
5. **Ollama** (https://ollama.com) — по умолчанию перевод идёт через модель Gemma. Скачать модель можно заранее:
   `ollama pull translategemma:4b` (3,3 ГБ) или согласиться на скачивание при первом запуске. Без Ollama можно
   переводить быстрым движком OPUS-MT (`--translator opus`), но для японского он ненадёжен.

При первом запуске скачиваются модели: распознавание речи (Whisper large-v3, порядка 3 ГБ, оценка),
OPUS-MT (по одной небольшой модели на пару языков), Gemma (3,3 ГБ).

## Запуск

```
python video_to_ru_subtitles.py "https://www.youtube.com/watch?v=..."
python video_to_ru_subtitles.py "C:\видео\ролик.mp4"
python video_to_ru_subtitles.py "C:\видео\список.txt"      # или .docx — сразу несколько видео
```

Запускайте **в терминале** (в VS Code — окно Terminal, не панель Output). Скрипт спросит:
что сделать с субтитрами и чем переводить (Enter = рекомендуемый вариант). Чтобы не отвечать каждый раз, задайте ключи или значения в блоке CONFIG:

| Ключ | Значения |
|---|---|
| `--glue` / `--no-glue` | склеить все видео списка в один файл или оставить отдельными (без ключа скрипт спросит) |
| `--captions` | субтитры YouTube вместо распознавания речи: `ask` (спросить), `manual` (готовые от автора), `any` (готовые, иначе автоматические), `off` (никогда) |
| `--quality` | качество скачивания: `max`, `1080` (Full HD), `720`, `480` (для ссылок; на файлы с диска не действует) |
| `--mode` | `srt` (только файл субтитров рядом с видео — быстрее всего), `soft` (дорожкой в .mkv), `burn` (вшить в картинку, перекодирование — долго) |
| `--translator` | `ollama` (Gemma), `opus` |
| `--model` | модель Ollama, например `translategemma:4b` (для `--translator ollama`) |

**Субтитры YouTube вместо распознавания речи.** Для ссылок на YouTube скрипт сначала узнаёт, есть ли у видео субтитры, и
предлагает взять их — распознавание речи (самый долгий шаг) тогда пропускается. Только с вашего согласия: показывается
меню (для списка — один общий вопрос заранее). Что может предложить:
готовые субтитры автора (на русском — перевод не нужен, на другом языке — переведём сами); автосубтитры YouTube на языке
оригинала (YouTube распознал сам, качество может быть ниже, чем у Whisper); автоперевод YouTube на русский (машинный
перевод машинного распознавания, к тому же YouTube часто отвечает на такие запросы ошибкой 429). По умолчанию (Enter)
берутся готовые субтитры автора, а если их нет — речь распознаёт Whisper. Если субтитры не скачались или не прочитались,
скрипт тоже распознаёт речь сам. Работает только для YouTube; для файлов и других сайтов — как раньше.

**Несколько видео сразу.** Передайте файл `.txt` или `.docx`: в нём по одной ссылке (или пути к видеофайлу) на строку.
Пустые строки и строки, начинающиеся с `#`, пропускаются; если в строке есть ссылка, остальной текст игнорируется.
В `.docx` берутся ссылки из текста, из таблиц и настоящие гиперссылки (нужна библиотека `python-docx`, она есть в
`requirements.txt`). Каждое видео обрабатывается отдельно: сбой одного не останавливает остальные, в конце печатается
итог, а неудавшиеся ссылки записываются в `work/retry_<дата>.txt` — этот файл можно передать скрипту снова, готовые
шаги будут пропущены. Параметры (режим субтитров, переводчик, качество) спрашиваются один раз на весь список.

**Склейка в один файл** (`--glue`, только для списков из двух и более видео). Субтитры подстраиваются под режим:

| Режим | Что получится в `subtitled/` |
|---|---|
| `srt` | склеенное видео `<имя списка>.mp4` и общий `<имя списка>.srt` рядом |
| `soft` | один `.mkv`: склеенное видео с дорожкой субтитров (общий `.srt` лежит рядом) |
| `burn` | один `.mp4`: субтитры вшиты, склеено в порядке списка (общий `.srt` тоже сохраняется) |

Время в общем `.srt` сдвигается на длительность предыдущих видео. Если у всех видео совпадает формат (кодеки, размер,
частота кадров, звук), склейка идёт **без перекодирования** и занимает секунды. Иначе все видео приводятся к размеру и частоте
кадров первого ролика (с чёрными полями) и перекодируются — на процессоре это долго, и во время работы временные
файлы занимают место в `work/` (удаляются сами). Ролик без звука получит тишину. Видео, которые не удалось обработать,
в склейку не попадают (они перечислены в итоге и в `work/retry_*.txt`). Отдельные `.srt` для каждого видео при склейке не
создаются: переводы лежат в `work/`.

Результат: `downloads/` (скачанное видео, при режиме `srt` и `.srt` рядом), `subtitled/` (для `soft`/`burn`),
`work/` (промежуточные результаты; при повторном запуске готовые шаги пропускаются).
Субтитры в режиме `srt`: откройте видео в VLC или PotPlayer — они подхватятся сами.

## Какой переводчик выбрать

Замеры автора на старом процессоре без пригодной видеокарты (Xeon 2016), секунд на реплику (по 20 реплик):

| Переводчик | ja | zh | de | es |
|---|---|---|---|---|
| OPUS-MT | 0,05 | 0,04 | 0,08 | 0,04 |
| TranslateGemma 4B | 3,7 | 3,2 | 3,1 | 2,5 |

На ролик в 1000 реплик это примерно: OPUS — около минуты, Gemma — около часа.

- **Gemma (по умолчанию)** — лучший перевод на всех четырёх языках и **единственный годный для японского**
  (понимает, что в японском часто опущено подлежащее). Но она медленная и иногда **молча искажает смысл**:
  перевернула «не менее уважаемый» в «менее ценный», придумала «монополизацию рынка», перепутала имя персонажа
  с пеликаном. Если важно, перепроверяйте имена и цифры.
- **OPUS-MT** — самый быстрый; для европейских языков (на тестах испанский, немецкий) и для коротких фраз на китайском
  давал связный перевод; лицензия Apache-2.0. Если прямой модели для пары нет, перевод идёт через английский
  (так было у китайского, немецкого и японского) — теряются детали. **Для японского ненадёжен**: на тесте выдал
  «(Аплодисменты)» вместо приветствия и несколько фраз не по смыслу.

Выводы сделаны по небольшим выборкам (по 20 реплик, один ролик на язык); французский не проверялся.
Для своего языка и своих роликов лучше сравнить самим (команда ниже).

Любой машинный перевод годится, чтобы **понять суть**; не цитируйте и не публикуйте без проверки.
Проверить, какой переводчик лучше для вашего языка, можно командой:
`python video_to_ru_subtitles.py "ссылка_или_файл" --compare` (20 реплик тремя переводчиками рядом, с замером скорости).

## Лицензии и ответственность

- OPUS-MT — Apache-2.0; Gemma — по условиям Google на Gemma. Если используете для работы организации — уточните
  допустимость заранее.
- Скачивайте только то, на что у вас есть права или разрешение правообладателя.

## Если что-то не работает

- «ffmpeg не найден» — не добавлен в PATH. «Нужен deno» при YouTube — положите `deno.exe` рядом со скриптом.
- Видео Facebook часто требует вход: впишите в CONFIG `COOKIES_FROM_BROWSER = "chrome"` (или `firefox`, `edge`).
- Распознавание на процессоре — самый долгий шаг. По умолчанию стоит `large-v3` (лучшее качество, особенно для японского и
  китайского; примерно вдвое медленнее `medium` — оценка). На слабом компьютере поставьте в CONFIG
  `WHISPER_MODEL_SIZE = "medium"` или `"small"` (быстрее, но менее точно). Результат распознавания кэшируется
  отдельно для каждой модели, так что смена модели пересчитает распознавание.
- Предупреждения Hugging Face про токен и символические ссылки на Windows безвредны.
- Китайский, японский, корейский: реплики переводятся по одной (склейка предложений для них отключена).
